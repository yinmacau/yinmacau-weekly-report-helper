## 4. 标准三：规则口径（无新公式）

**已转正**：沿用线上提示词与大纲、既有不编造红线和篇幅档位（低约 600–900 字，中约 700–1200 字，高约 1200–2000 字）。不得套用新人大纲。【只读实际观察】

**新人输出结构与原则**（【源于协调方可视核对转录，PM未直接读取原图】；提示词可用简体标题，语义不得减项，不强制输出繁体，语言跟随草稿）：

- **Summary（已确定，非待核）**：条列梳理「学习项目、内容摘要、完成状况」。不强制 Overall 1–2 句，不强制表格样式；用了也不因此不合格。
- **Details 1 本周学习内容**：参考 STAR，展开个人理解与思考及收获；价值（知识/技能背后的目的）；对比（与过去经验异同）；比喻（用什么比喻或例子向同事解释）。STAR 缺项不得补编。【用户原话确认·经总管转述】草稿未写「价值」「对比」「比喻」时，必须根据草稿上下文自行补写这三项，结果中不得留空、不得只把缺口放进「待补充问题」。这三项是允许的上下文推断，须与草稿已有学习内容相符，不是自由编造数字、人员或未发生的经历。
- **Details 2 问题与挑战**：学习中的挑战（技术/流程/思维/认知）及是否需导师或同事协助；困难、解决思路与结果；对流程/系统等的疑问、改善机会、后续推进与是否需协助。
- **Details 3 iTeam**：协作收获与帮助；建立 iTeam List。「与 F1 & FX 同事（EPM，周边单位）」及「e.g. 了解个性，跨部门沟通，信息分享」是框架举例，**不是用户事实**。名单只能源于草稿。
- **Details 4 下周学习计划**：与导师沟通，用 SMART 列出学习项目与具体目标。无材料的数字、截止日期、衡量标准不得补编。
- **图2原则**：深度重于广度——不罗列全部事情，选关键案例深入剖析。真实重于准确——真实理解和想法比正确答案更重要，以便导师及时发现困难、带回正轨。此条不授权编造无关事实或用标准答案、套话、其余五张示例数据填空；不禁止按上条对价值 / 对比 / 比喻做上下文推断。

**材料不足**：Summary 与 Details 四段标题必须保留。除「价值 / 对比 / 比喻」外，其余缺口列入文末「待补充问题」（沿用已有机制，正文中不插【待补充】）。**不得把未知写成「无」**（例如不得写「本周无挑战」「无 iTeam」来冒充已核实的空缺）。价值 / 对比 / 比喻不按「缺则待补充」处理：只要草稿有可推断的学习内容，就必须补写。【用户原话确认·经总管转述】若草稿完全没有可推断的学习内容，标题仍保留，说明上下文不足并列入待补充，仍不得写成「无」。文首建议沿用 `# 周报 | {姓名} | {周期}`，缺则【待补充】。

可复核（示例，非用户事实；【用户原话确认·经总管转述】）：草稿仅有学习内容与收获，如「读懂了登录页报错，以前没注意校验顺序」→ 结果必须出现与该上下文相符的价值、对比、比喻（三者均有实质内容，不得留空或只进待补充）；同时不得出现材料没有的数字、人员或协作（如「降低 X%」、与 F1 协作、虚构 iTeam 名单、「课程 100% 完成」），也不得把这些未知写成「无」。草稿仅「下周想再走一遍鉴权并和导师对疑问」→ 可写这两项，不得补「11 月 21 日前 / 掌握 80%」等 SMART 数字或日期。同一草稿走已转正，仍须是旧大纲。

【协调方案·非用户逐字确认】新人沿用「润色程度」低 / 中 / 高（默认中），档位只调展开深度，**不套用已转正字数区间**，且不得因「高」档改成罗列全部事项。

## 5. 标准四：状态与权限

角色仅本机使用者，无审核流，不新增审批。生成状态沿用线上：空闲 / 请求中 / 流式输出中 / 完成 / 失败 / 已中止。中止部分结果可留在结果区，不自动入历史。完成态结果仍可本地编辑。

【转述硬要求】一次「开始润色 / 再改一版」所用提示词、结果写入位置、历史模式，应等于**启动时**的模式，而不是结束时界面上的模式；再改一版须沿用该结果所属模式的规则。

【协调方案·非用户逐字确认】首次打开默认「已转正」，并记住上次选择。切换不清空，分模式保留草稿 / 结果 / 修改意见。请求中或流式输出中禁止切换模式；可复用既有文案「请先停止当前润色」（与现有生成中载入历史一致，不另造一句）。空闲、完成、失败、已中止可切换。
